# Design Decisions & Gotchas

[All documentation](README.md)

Things that look wrong or slow but are deliberate. Read before "fixing" them.

- **Outline notch probes use boundary distances.** A point lies inside a polygon eroded by a distance only when it is inside the polygon and farther than that distance from every boundary, including holes. `outlineExtrude` tests this directly, avoiding a full Clipper erosion per recursive band and chord-error slivers that cause extra sections. Keep the band-width plus 0.02 mm clearance and the narrow-notch/closed-mesh tests. The detailed smile fixture has a deterministic polygon-offset budget; `bun run benchmark:outline` measures the actual Chromium build cost.

- **SVG outline sizes artwork before its border.** Each face independently fills Width, without padding, then its physical mirror is applied. Both refined silhouettes are unioned with counters filled and offset in mm with rounded Clipper joins. Disconnected results (including point contacts) block the build before keyring attachment. A reinforced keyring attaches in the selected direction, with its hole clear of the artwork. Flat faces carry the requested offset; bevels bulge out as on other plates. Outline bevels loft nested polygon offsets, allowing notches to close without folded vertex bevels; sections are at least 0.02 mm apart so their rings nest strictly, and bands triangulate from those rings directly (no boolean op, exact shared vertices). Only a band whose all-old-boundary triangles lie deeper than its width inside the new section (a closing notch) is subdivided. At zero offset, flat plates' recess cutters reach 0.001 mm past the plate edge, and chamfered plates get a 0.0001 mm clearance instead, so CSG never sees coplanar exterior/recess walls; outline recesses always use CSG, including through-inlays. See [outline plates](outline-plates.md).

- **Outline keyring angles rotate the attachment frame, never the artwork.** `keyringAngle` is clockwise from Front's top (0/360 top, 90 right, 180 bottom, 270 left); old saves default to 0. The hole stays on the radial center line in that frame, and the outermost boundary crossing anchors the capsule neck. Following the highest tip instead makes adjacent angles jump between distant tips (271–272° on the smile wordmark). Hole placement keeps 1 mm from the convex envelope of the combined silhouette, measured to its exact segments by a monotone radial distance search. The convex envelope is only for placement: it keeps movement smooth across concavities while distant sideways tips no longer force long necks (217° on the smile wordmark). The plate retains its actual concave outline, and both faces stay clear of the hole. Pockets enclosed by the neck are filled before cutting the keyring hole. Snap circle axis crossings exactly to the capsule sides before clipping; clipping rotated tangencies can still leave adjacent vertices only ~1e-15 mm apart, so remove those below 1e-8 mm before triangulation. Earcut can also skip a collinear boundary vertex when bridging a hole; split exposed cap edges at those vertices so caps and walls share edges. Rectangle/Circle ignore the saved angle, and disabling the keyring retains it.

- **Face orientation is an outside view with artwork upright.** Front is the positive-Z plate face. Back's outside-view X axis opposes the plate's X axis; its horizontal mirror toggle is composed with that reversal. Both X mirroring and the SVG Y flip are baked into the inlay vertices with winding repaired, and the same mapping is used for recess outlines. The compatibility same-image setup has Front unmirrored and Back mirrored, preserving legacy geometry; unchecking Back makes both faces read normally from outside. Moving the outline keyring does not rotate either face view.
- **Faces own sources; Empty retains them.** Each source keeps its SVG, filename, refinements, import failure and uploader generation. Back's Same as Front mode uses Front's source and refinements, while keeping its own mirror; its previews are read-only, with editing available on Front. Switching modes never destroys the inactive source. Both uploaders stay mounted, so a late read or trace cannot land on the other face. Only sources used by populated faces gate export; a blank plate can be exported directly. New pending/failed imports persist as failures, distinct from deliberate Empty selections. Retracing retains the last valid SVG across reloads; an actual retrace failure still invalidates it.
- **Printer capabilities are shared.** Nozzle size and Single-line walls (`nozzleDiameter`, `thinWalls`) live in one persisted printer profile used by both faces and plate warnings. Old per-face saves migrate Front's settings. Refinement changes save only metadata, not the SVG. Unused sources retain their parsed artwork but skip refinement geometry and thin-feature raster checks until reactivated.
- **Fresh artwork reads normally from both sides.** Back defaults to Same as Front with Mirror off. Only pre-two-sided saved artwork migrates to Back mirrored, preserving its original plate coordinates; explicit saved mirror choices always win.
- **Saved face SVGs survive missing metadata.** If a quota failure or corrupt metadata leaves a face's SVG on its own, reload restores that source as independent, unmirrored artwork with default refinements. Only faces without either usable metadata or a saved SVG fall back to legacy state. Missing SVGs with `hasArtwork` metadata still restore as import failures.
- **Camera inspection has explicit face views.** Front/Back buttons look at each outside face with artwork upright; Reset View restores the isometric view. These actions render without rebuilding. There are no axes or fixed-size grid helpers through the model.
- **Plate fitting uses both populated faces.** Each rectangular image independently fills the padded target width, and the taller image determines the shared height; both are centered. Circular images independently fit their farthest point to the padded radius. These scales match `fitGroups` in refinement and printability measurements. Empty faces contribute no bounds.
- **Meeting-depth shortcuts require equivalent physical faces.** The through-inlay and unbeveled through-hole paths are used only when both faces share the same refined groups array and physical X mapping. Different/empty faces get their own half-depth inlays and matching blind recesses. Disjoint recess cutters are merged; touching cutters are CSG-unioned before one subtraction, removing coincident internal caps. Extrusion Z endpoints are assigned directly, avoiding double Float32 rounding that could separate nominally touching halves of a 0.8 mm plate.

- **Desktop keeps both face editors visible.** At 1024 px and up, Front and Back occupy adjacent, independently scrolling columns; a narrower right column holds 3D inspection, export, and the Keychain settings (plate, inlay depth, keyring) and Printer cards. The workspace is capped at 1680 px and has no horizontal page or editor scrolling. An enlarged 2D preview occupies the right column, leaving both face editors usable. Its thin-area toggle is synchronized with that face's inline preview; each face keeps its own overlay visibility.
- **Basic view hides options, never their effect.** One app-wide Advanced options switch (`useAdvanced`, persisted, kept by Start over) shows every setting. In basic view an advanced control still renders when its value differs from the default, when a constraint adjustment, printability warning or config error names its field, or (for trace options) after a trace fails; paired controls (hole/loop size, chamfer/roundness) show together. Remove small details is an explicit exception: its controls and tiny-island advice appear only in advanced view, even when its saved threshold is nonzero; hiding it preserves its effect. The other controls follow the visibility rule so a hidden, changed or clamped value does not silently shape the model.
- **Trace Colors counts printed colors.** When Remove background will drop an opaque border color, `traceImage` quantizes to one extra cluster, so the setting matches what is printed. The default is 5 (formerly 6 including the background).
- **Logo cutouts are cut with CSG, not `shape.holes`.** `ExtrudeGeometry` bevels every contour, including holes, so logo holes in a beveled extrusion would get beveled edges and the inlays wouldn't sit flush. A hole also runs through the entire extrusion and cannot leave a recess floor. The plate is extruded with only the outer edge and keyring hole beveled, then straight-sided surface recesses are subtracted with `three-bvh-csg` (`cutoutBasePlateHoles` in `src/utils/meshBuilder.ts`). Both faces' cutters share one CSG evaluation. Exception: when the bevel is ≤ 0.01 mm and the inlays meet through the plate, the cutouts go straight into `shape.holes` with counter islands and CSG is skipped. Shallow recesses still use CSG without bevel.
- **Logo depth is per face, measured in mm.** `logoDepth` defaults to 0.6 mm (three layers at 0.2 mm). Choose a multiple of the slicer's layer height; the app does not change slicer settings. Recesses and inlays use the same Z intervals, leaving a continuous middle in the plate material. The depth is capped at half the thickness without changing the raw slider value. When two equivalent physical faces meet, one through-inlay replaces the two shells, avoiding overlap and coincident internal caps. The two shells otherwise share one mesh/material per color for preview and 3MF export. Bevels ≤ 0.01 mm count as zero for both plate and inlays. See the [slicer comparison](surface-inlays.md) for measured print savings.
- **The keyring hole *is* beveled on purpose.** It's added to `shape.holes` before extruding so its inner edge gets the bevel. Only the logo cutouts go through CSG.
- **Keyring sizes and minimum walls are measured at the flat faces.** The hard minimum face wall is 0.4 mm; a 6 mm loop allows holes up to 5.2 mm. Artwork clearance is a separate 1 mm rule, including the outline attachment's convex placement envelope. The chamfer bulges the outer loop outward and the hole inward, so the middle wall is `(loop diameter - hole diameter) / 2 + 2 × effective bevel`. A 6 mm loop with a 4 mm hole has a 1 mm face wall and a 2.2 mm middle wall with the default 0.6 mm chamfer. Strength advice shows both when chamfered; slicer perimeter counts through the middle describe the thicker section.
- **Refinements never edit the SVG.** They're stored as settings (`Refinements` in `src/types/keychain.ts`) and applied to the parsed color groups before the model is built (`src/utils/refine.ts`, wired up in `useLogoRefinement`). The parser doesn't know about them, and every edit can be undone. Recolors and hidden shapes refer to the current logo (shapes by `color:index`), so they reset on a new upload; the cleanup settings carry over.
- **Each refinement step returns a new array only when its output changes.** Because groups are compared by identity (below), `refineColors` and `removeSpecks` keep their last result per input and return it again when nothing changed (e.g. a merge tolerance below every color distance). Otherwise every slider tick would trigger a ~400 ms rebuild.
- **Speck sizes and thin features are measured at the printed size.** Both use the logo scale from `fitLogo` (`src/utils/logoFit.ts`), the same function the builder sizes the plate with, so they follow width, padding and plate shape. Specks use the scale before they're removed; removing them barely moves it.
- **Outlines are simplified as a shared-border graph, not ring by ring.** `simplifyGroups` (`src/utils/simplify.ts`) uses Ramer–Douglas–Peucker with the tolerance in mm at the printed size, not a minimum edge length, which would blunt sharp corners and miss long, gently curved runs (every curve is tessellated into 16 segments, however small). Neighboring colors share borders, and simplifying each ring on its own would open seams or overlaps between them. So points are merged across rings, vertices lying on another ring's edge (T-junctions polygon-clipping leaves where regions meet) are inserted into that edge, and every border between junctions is simplified once for all the rings along it. Pieces thinner than the tolerance collapse and are dropped, and their neighbors close over them. It runs last in the refinement chain, so it also shrinks the CSG cutouts and speeds up rebuilds.
- **Thin features are only flagged, not fixed, and the check is raster-based.** Thickening needs a polygon offset, which polygon-clipping can't do (Clipper2 could). `findThinFeatures` rasterizes the colors and the plate gaps and runs a morphological opening with exact distance transforms (~30 ms, debounced). Every acute corner fails by a sliver, so areas under a quarter of the minimum width squared are ignored; tips sharper than ~45° are still flagged, because they really do print blunt.
- **PNG tracing goes through SVG, and smooths borders, not regions.** `traceImage` (`src/utils/traceImage.ts`) quantizes colors, then treats the borders between colors as one graph on the pixel-corner grid, with junctions (three or more colors meeting) fixed. Each border is smoothed once for the colors on both sides, so neighbors stay sealed without the shared-border simplifier. Per border: Gaussian smoothing and Ramer–Douglas–Peucker take out the pixel staircase (plain RDP keeps its notches; smoothing alone leaves kinks along nearly straight runs), then Potrace's tests split the polygon into corners and curves. A point is a corner when it stands out from the line between its edges' middles by more than the *round corners* setting times the simplification tolerance (which grows with smoothing, so a coarser polygon doesn't turn curves into corners). Corners go back to where lines fitted to the unsmoothed pixels meet, because smoothing rounds them off. A corner that anti-aliasing cut into two close points between long edges is restored the same way, but only between long edges, or the steps of an O would become sharp. Every other point becomes a quadratic curve from edge middle to edge middle, and is first moved to where lines fitted to the smoothed border meet, or curves shrink inward. Anti-aliasing clusters are recognized by color *and* position: a color lying between two bigger ones is dropped only if most of its pixels sit on borders, otherwise a real color (gold between coral and white) is lost. One-pixel hairlines left along borders (blends that matched a real color) are cleared with the lone pixels. The background is the corners' color flood-filled from the border, not every pixel of that color, so white letters on a white page survive. The result is an ordinary SVG, so a traced logo is persisted, refined and exported like any upload.
- **The camera refits for a new SVG, not for refinements.** `ThreeViewer`'s `fitKey` follows both parsed groups arrays, so hiding a shape or merging colors rebuilds the model without resetting your view.
- **Config changes are debounced, not throttled.** `ThreeViewer.vue` waits for 60 ms with no input before rebuilding. While inputs keep arriving within that window nothing rebuilds; the model updates after you pause. CSG builds are synchronous, so input complexity is bounded before building and export stays disabled while a rebuild is pending.
- **Import attempts invalidate old artwork.** A new upload clears the affected source's old parsed/persisted SVG immediately; the other source stays intact. Decode, read, trace, and validation failures leave no stale logo in the scene. Each async read/decode belongs to an upload generation, so a late result cannot overwrite a newer upload. Retracing preserves the mounted 2D preview and its zoom while pending, then invalidates artwork if it fails.
- **Export readiness follows the current build.** The viewer reports pending, ready, failed, or unavailable states. Its export group is unavailable while inputs are pending; WebGL/build/import failures disable Download. A plain plate needs no import; set both faces to None for one. There is no Print logo toggle: a printed keychain without its artwork wasn't useful, and None per face covers it. The filament summary counts distinct printed colors across the plate and both faces, including shared plate/logo colors only once.
- **Partial previews never become exportable models.** Import failures clear only their source. `planArtworkPreview` excludes faces over the geometry budget; when two individually valid sources exceed the combined budget, Front remains inspectable and Back is explicitly omitted. Shared sources count once. A runtime build failure tries current faces independently. These previews show an omission label and disable Download; the viewer's export accessor returns null. Dimensions on a partial preview describe that preview, and may change when the full artwork is repaired. Blocking feedback above the viewport is announced once; matching details beside source controls are not separate live alerts.
- **Rendering is on demand.** `useThreeScene` only draws when `requestRender()` is called (or while orbit damping settles). Any code that changes the scene must call `requestRender()` or `fitCamera()`, or the change won't appear until the next mouse move.
- **`colorGroups` is compared by identity.** The viewer's watcher isn't deep, and the logo outline union is cached per array instance (in `logoOutline`). A new SVG or refinement must produce a new array; changing the old one in place won't trigger a rebuild or a new outline.
- **The logo's mirror and scale are baked into the geometry.** The SVG's Y flip is a negative scale. Putting it on a group transform would export to 3MF as a mirrored node, which slicers handle inconsistently, so it's applied to the vertices instead.
- **The model is built from clamped config, not the slider values.** `constrainConfig()` clamps combinations that break the geometry (e.g. a keyring hole bigger than its ring, or padding that would eat the whole logo). The UI keeps your raw values.
- **`ThreeViewer.vue` edits force a full page reload in dev.** It owns a WebGL context that can't be hot-swapped safely; swapping it in place would leak a context on every save.
- **The build profiler only runs in dev.** `src/utils/profiler.ts` logs a collapsed `[keychain build]` table to the console on every rebuild in `bun run dev`, and does nothing in production builds.
- **CSG acceleration trees are prepared explicitly.** `three-bvh-csg` 0.0.17 uses the deprecated `maxLeafTris` option with the installed `three-mesh-bvh`. `meshBuilder.ts` supplies the equivalent indexed, indirect trees using `maxLeafSize: 3` so ordinary builds do not emit deprecation warnings. Keep the triangle order and CSG build order unchanged.
